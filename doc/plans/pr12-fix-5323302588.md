### Why builder integration is the right matcher home

```text
test_extract_title_...  --> extract_title(..., "gpt-5-nano", ...)
                            proves: explicit arg is sent

test_dry_run_stops_...  --> Config { model: "gpt-5-nano".into(), ... }
                            proves: explicit Config.model is sent

test_builder_config_... --> Config::builder(...).build()  // no .model()
                            proves: builder default reaches the wire
```

Only the third path fails if someone later hard-codes a divergent builder default
while leaving `DEFAULT_MODEL` and the resolve pin alone (or the reverse split).

### 5.3 Cycle C - `TEST_DEFAULT_MODEL` refactor (review #3)

While green, in each of `src/pipeline.rs` and `src/title.rs` inside `mod tests`:

```rust
#[cfg(test)] // redundant inside cfg(test) module but documents intent if hoisted
const TEST_DEFAULT_MODEL: &str = "gpt-5-nano";
```

Replace default-shaped `"gpt-5-nano"` literals in that module's tests with
`TEST_DEFAULT_MODEL` (including `body_partial_json` and mock body `"model"`).

Leave config product pins on raw `"gpt-5-nano"`.

Leave intentional overrides (`"gpt-4o"`, `"o3"`, etc.) untouched.

### 5.4 Cycle D - Scoped CLI help asserts (review #5)

Replace full-help scanning with arg-local help:

```rust
#[test]
fn test_model_flag_help_lists_gpt_5_nano_default() {
    use clap::{CommandFactory, ArgAction}; // only what is needed
    let cmd = Cli::command();
    let arg = cmd
        .get_arguments()
        .find(|a| a.get_long() == Some("model"))
        .expect("Cli must expose --model");
    let mut help = String::new();
    if let Some(h) = arg.get_help() {
        help.push_str(&h.to_string());
        help.push(' ');
    }
    if let Some(h) = arg.get_long_help() {
        help.push_str(&h.to_string());
    }
    assert!(
        help.contains("gpt-5-nano"),
        "expected --model help to mention default gpt-5-nano, got: {help:?}\nfull={help}"
    );
    assert!(
        !help.contains("gpt-4o-mini"),
        "stale default gpt-4o-mini still present in --model help: {help:?}"
    );
}
```

Natural RED options (pick one if available before editing production comments):

1. If current implementation still uses full long-help, first change the test to
   look up a **wrong** long name (`"models"`) and expect `expect("--model")` to
   fail - proves the finder is what the test relies on - then fix the finder.
   Prefer not to land the wrong-name version; use it only as a local RED probe.
2. Practical sequence on already-correct help text: rewrite asserts to arg-local;
   run test - should stay green (lock). Then temporarily edit the doc-comment
   default to `gpt-4o-mini` locally to confirm the test goes RED, restore
   comment, re-run green. That local sabotage is a **confidence probe**, not a
   commit.
